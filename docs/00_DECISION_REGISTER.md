# Decision Register

| 항목 | 값 |
|---|---|
| Document ID | DOC-CORE-020 |
| 문서 버전 | v1.7 |
| 상태 | IN REVIEW |
| 소유 역할 | Architecture Owner |
| 기준일 | 2026-09-12 |

이 register는 mrHOMES AI MLS의 중요한 architecture 및 governance decision을 한 곳에서 추적한다. 상세 근거와 대안이 필요한 결정은 [ADR workflow](adr/README.md)를 사용하고, 변경 요청은 [Change Request Register](00_CHANGE_REQUEST_REGISTER.md)에 먼저 기록한다. 이 register의 행은 ADR을 대체하지 않는다.

## 값 규칙

| 필드 | 규칙 |
|---|---|
| Decision ID | 다음 미사용 `DEC-NNN`; 재사용 금지 |
| Related ADR | `ADR-NNN` 또는 ADR가 필요 없는 founding mandate의 근거 문서 |
| Decision Type | `Architecture`, `Business`, `Security`, `Database`, `API`, `AI`, `Workflow`, `Deployment`, `UI` 중 하나 |
| Decision Date | 최종 승인일 `YYYY-MM-DD`; 승인 전 `—` |
| Status | `PROPOSED`, `UNDER_REVIEW`, `APPROVED`, `REJECTED`, `DEFERRED`, `SUPERSEDED` |
| Affected Documents | permanent Document ID 목록 |
| Affected Phase | Brief, development phase 또는 `ALL` |
| Superseded By | 대체 Decision ID 또는 `None` |

`APPROVED`는 [Approval Workflow](00_APPROVAL_WORKFLOW.md)의 증거가 있을 때만 사용한다. architecture를 변경하는 결정은 관련 ADR과 [Traceability Rule](00_TRACEABILITY_RULE.md)의 downstream impact를 연결한다.

## AO-017 change-control rationale

### Problem

Frozen registries가 Publication Approval을 SP-007에 배정했으나 SP-007은 이미 Permission Authority로 구현, 승인, 동결됐다.

### Decision

Publication Approval Authority artifacts를 SP-008/REL-003으로 재배정하고 기존 SP-008 RC stabilization scope를 SP-009로 이동한다. SP-007 Permission Authority baseline은 변경하지 않는다.

### Rationale

- accepted SP-007 baseline을 보존한다.
- frozen Sprint를 다시 열지 않는다.
- Permission과 Publication Approval의 분리를 보존한다.
- sequential implementation ownership을 유지한다.
- canonical registry의 silent reinterpretation을 방지한다.

### Consequences

- TRACE-014는 SP-008/REL-003으로 이동한다.

### Scoped refinement rule

DEC-109와 DEC-111은 DEC-100/101/104 전체를 폐기하지 않는다. 기존 Decision은 `APPROVED` 상태를 유지하며 다음 문장 범위만 더 최신의 구체적 결정이 우선한다.

- DEC-109: Non-material Correction은 기존 Publication의 append-only Correction이고 Material Change만 Successor를 생성한다.
- DEC-111: Republish는 동일 Publication intent의 새 authorized Command/Attempt이며 Successor 또는 retry로 간주하지 않는다.

따라서 AO-023–AO-035 중 `SUPERSEDED` 또는 `DEPRECATED` Decision은 없다.

## 관리 절차

1. decision proposal은 관련 `CR-NNN`, risk, assumption과 affected trace ID를 연결한다.
2. Architecture Review Board는 type별 reviewer와 ADR 필요 여부를 결정한다.
3. 승인·거절·defer 근거를 [Approval Workflow](00_APPROVAL_WORKFLOW.md)에 따라 남긴다.
4. 변경 시 기존 행을 덮어쓰지 않고 새 decision을 추가하여 `Superseded By`로 연결한다.
5. release 전 [Release Policy](00_RELEASE_POLICY.md)의 checklist에서 신규·변경 decision의 반영을 확인한다.

DEC-001–007의 approval evidence는 founding mandate, Phase 14 recommendation과 Phase 15 user authorization으로 backfill했다. Named assignee 지정은 `OD-ROLE`로 D0 entry까지 유지한다.
